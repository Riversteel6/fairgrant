# 给参赛联系人的讲解稿

FairGrant 是分配计算器，不会转钱，也不需要钱包。

想象给三个人分10个单位，贡献权重为6、3、1，但前两个人最多拿3、4个。
直接按比例会给6、3、1，第一人超上限。只把第一人压成3，又会剩3个无人分。
我们的程序重新分配：第一人固定3，再计算剩余7；第二人触及上限4，最后一人拿3。

如果给三个人平均分10，不能分成3.333个最小单位。先各给3，剩下1个交给
小数余数最大者；余数相同就按预先固定的输入顺序。这会得到4、3、3。

你需要能解释的五点：
1. 核心算法用Fe写，Python负责独立检查答案、导入CSV、输出报告；每个预算方案仍调用真正的Fe程序计算。
2. 所有金额是整数最小单位，内部用更宽整数算乘法，防止先溢出再除法。
3. 零权重的人不参与，合格人的上限加起来不够时，程序明确返回未分配余额。
4. 输出capped说明上限约束生效；rounded_up说明获得了一个尾差单位。
5. 这不是“绝对公平”的算法，预算增加时个别人的数额反而可能减少，文档有反例。

AI披露：架构、代码、测试和文档由OpenAI助手辅助完成。不要声称自己独立写了全部代码，
也不要声称外部审计或保证获奖。联系人才是负责解释作品、接收赛事邮件的人。

运行方式在README。建议自己跑一次3/4/3例子，再把预算改成9或11，看输出如何变化。

实际演示：按README生成review-community和review-risk，用浏览器打开index.html。前者展示三类贡献的300/400/300分配，后者用警告明确显示预算从25增加到26时Team D和E反而从3降为2。报告用于先审查再决定，不会自动支付。输入顺序应事先确定，不能为了想要的结果反复改顺序。
